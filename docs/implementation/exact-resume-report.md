# Explicit reading-position Resume

Implemented October 2, 2026. The chapter stores its latest reader viewport separately from `maxProgress`; moving backward replaces the saved viewport without lowering furthest progress or changing completion. A final stop/pagehide measures pending scroll before flushing, while route changes flush only previously measured evidence.

Version 4 migrates chapter records without inventing viewport coordinates for old chapters. Saved positions contain numeric dimensions and an optional image index/fraction, no HTML or selectors. Message payloads validate coordinates, source tab/chapter ownership, current route, policy and progress revision. Out-of-order and future-dated positions cannot overwrite newer evidence. Existing manual corrections invalidate old positions with their durable revision.

Browser integration exposed that Chrome can discard a final message after its tab closes. Settled scrolls now checkpoint during the live page, with 250ms coalescing and a 300ms minimum write interval plus a trailing checkpoint. Hidden pages measure before flushing. The existing closed-tab authorization remains strict. Backward/unchanged-progress checkpoints update the chapter without recalculating summaries or broadcasting whole-library changes; actual forward progress still persists its furthest value.

Computed Resume (or an explicit `continue/open` `resume: true`) registers a short-lived tab intent in local `chrome.storage.session` before navigation. Worker termination does not lose the intent. Nothing is added to the website URL. The validated matching chapter consumes it once. Ordinary browsing, chapter history links and Next chapter do not restore positions.

Restoration uses the image-relative anchor where available, otherwise proportional reader/document offset. It settles changing image dimensions and late reader markup for a bounded 12 seconds, stopping immediately for reader input, route/pagehide, policy revocation or manual progress revision change. Restoration itself cannot add reading time, progress or completion. Paged readers retain their site's navigation controls; a scroll offset cannot reliably select a page. Responsive content reflow, replacement chapter artwork and readers taking longer than 12 seconds may produce an approximate position. Legacy chapters obtain a position after a fresh reading visit.

Focused unit coverage includes backward viewport persistence after database reopening, stale revisions, malicious coordinates, late image sizing, SPA delay, manual input cancellation, manual unread during settling, final debounce flush, route evidence isolation, per-tab one-use intent before navigation, ordinary visits, source/frame/route/revision/policy rejection and intent expiry. The first integrated `npm run check` passed 231 tests across 34 files, TypeScript and production build; later focused policy tests also passed. Parent integration owns final browser acceptance, UI review and packaging.

Live-checkpoint regressions reproduced the browser failure with a short 950ms forward/backward session, continual scrolling with bounded sends and a trailing final position, and visibility change before debounce. All three failed before the fix and passed afterward. The updated integrated `npm run check` passed 238 tests across 34 files, TypeScript and the production build.
