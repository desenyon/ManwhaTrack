# ManwhaTrack audit — October 1, 2026

Historical snapshot before implementation. The accepted fixes and revised Violet / Folio direction are implemented in the extension; see [current verification](../implementation/verification.md). Baseline results and original reproduction expectations below are preserved as audit evidence.

The extension has a substantial, appropriately local implementation. The main problem is reliability at the boundaries between automatic tracking, manual correction, imports, and multiple sources. Those problems deserve priority alongside the UI refresh. A new framework or wholesale rewrite is unnecessary.

This is an audit and design proposal. Production code is unchanged. The additional tests below deliberately assert the desired behavior and currently fail, exposing the defects. They are isolated from the normal test suite.

- Reproductions use the real storage and message-handler implementations with fake IndexedDB. The privacy check exercises the receiver with a stale incognito progress message; it is not a browser demonstration of a complete preference-toggle flow.

- Visual review used the repository's existing light library and dark detail screenshots, plus the current UI implementation and CSS. Those are archived screenshots, not freshly captured evidence. Aside CLI could not connect to its browser. Live UI verification remains distinct from source review.
- The codebase graph initially reported the project unindexed. It was indexed as `Users-naitikgupta-Projects-ManwhaTrack`; local source inspection was used while the graph calls were delayed.

### Fix boundaries and acceptance checks

**A1:** Apply incognito, ignored-host, and sender/chapter ownership checks at every automatic write boundary, including completion from Next links. Stop the content tracker when a preference revokes tracking; re-evaluate when settings enable it. Initial incognito-off startup is guarded already. Acceptance: turn tracking off on an active incognito chapter and verify no subsequent progress/time/completion writes; repeat for ignored hosts.

**A2:** Treat IndexedDB and Chrome preferences as separate persistence steps. Report partial success precisely or implement a deliberate recovery strategy. Do not promise rollback that does not exist. Acceptance: inject failure into each storage layer and verify the reported outcome matches the committed state.

**A3:** Separate merging independent reading records from merging a repeated backup snapshot. Counters must be idempotent when the same chapter snapshot is imported again. Acceptance: export/import the same data repeatedly and compare all counters, progress, notes and event IDs.

**A4:** Preserve detected identity separately from the editable label/number and reconcile canonical URLs when updating a chapter list. Changing display metadata must not create a second identity. Acceptance: correct a chapter, revisit both chapter and series pages, and verify one record with the override retained.

**A5:** Reset or explicitly override completion evidence when progress is lowered. Synchronize active content trackers so their in-memory maximum cannot undo the user's correction. Acceptance: lower progress and mark unread while the chapter tab remains open, then scroll, idle, reload and revisit.

**A6:** Keep original source URLs as historical metadata. Prefer a matching chapter on a remaining source, or its series page, when the old source is removed from active use. Do not relabel an old website's URL as belonging to a new website. Acceptance: remove a source and verify every active Continue destination belongs to a remaining source while history survives.

**A7:** Validate that fetched/redirected observations still identify the tracked work before applying its chapter list. A same-host redirect is insufficient. Acceptance: redirect to another series, search/listing page, and error page; all must preserve existing progress without ingesting unrelated chapters.

**A8:** Build one set of exported series IDs and filter sources, chapters, history, queue and covers consistently against it. Acceptance: export mixed active/removed series and parse the result without orphan-record warnings.

## Additional source-review findings

These were identified in the implementation. They should receive targeted browser or fault-injection tests before being counted as end-to-end reproduced failures.

1. **Silent tracking loss after a transient message failure.** `src/content/index.ts:run` assigns `lastReportKey` before sending; `send` suppresses errors. A repeated detection with the same key will return without retrying. Preserve a pending observation and set the successful-report key after acknowledgment.
2. **Progress lifecycle lacks resume handling.** `src/content/reader-progress.ts` permanently stops on `pagehide` and has no `pageshow` restart; delayed callbacks are not canceled and do not check `stopped`. Test restored pages and route changes before replacing this lifecycle.
3. **Reading-time activity is incomplete.** `isActive` checks document visibility and recent activity, but not focus or whether chapter content is active. A visible tab in an unfocused browser window can accrue time during the idle allowance. Add focus/reader-activity evidence and test actual browser conditions.
4. **Automatic cover failure is invisible.** `src/background/covers.ts:cacheDetectedCover` only logs a download failure; it does not persist the promised error state. The user cannot distinguish “no cover detected” from “download failed” or know which source to retry.
5. **Update-check locking is not atomic.** `src/background/update-checker.ts:acquireLock` reads then writes `chrome.storage.session`; concurrent alarm/manual calls can both observe no lock. Serialize acquisition, retain a restart-safe lease, and test simultaneous requests.
6. **Some destructive actions have neither confirmation nor Undo.** The duplicate banner merges immediately; individual history events and site rules delete immediately; source removal also lacks Undo. See `HomeView.tsx`, `HistoryView.tsx`, `Rules.tsx`, and `SeriesView.tsx`. Confirmation is present for full reset/history clears, so the pattern is inconsistent.
7. **Some optimistic operations have no rollback/error state.** Queue writes in `useActions.ts` and `QueueView.tsx` update UI before awaiting storage and do not restore state on rejection. Shared `useLibrary.mutate` captures rollback state inside a React state-updater callback and restores a whole series array; overlapping updates need a fault-injection test to ensure a failed change cannot erase a newer successful one.

## UI audit

The current UI gets several fundamentals right: compact rows, system fonts, quiet borders, local covers, a prominent per-row reading action, light/dark support, and restrained copy. Preserve them.

Its weak point is hierarchy and interaction completeness. The archived library screenshot is mostly a flat toolbar, tabs, uniform rows and empty space. The detail screenshot spends early visual attention on title/alias editing, rating and status, before the reading action and reading position. The blue is an ordinary control accent rather than an intentional visual identity.

| Finding | Evidence | Upgrade |
|---|---|---|
| Secondary text is too faint | `--text-3` is `#83878d` on `#f7f7f5`: **3.37:1**. Dark `#7d828a` on surface `#1e2125`: **4.18:1**. These tokens appear on small informational text. | Raise contrast for dates, sources, field labels and secondary facts. Ordinary text needs 4.5:1 under [WCAG contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). |
| Modal behavior is incomplete | `src/ui/Menu.tsx:Dialog` focuses an initial control and handles Escape, but does not contain Tab focus or make the underlying interface inert. | Implement focus containment, restoration and background isolation for all dialogs. |
| Grid batch selection has no visible selection state | `SeriesTile` does not use `checked` or render a selection control, although its click changes batch selection in `HomeView`. | Expose a checkbox/checked treatment consistently in grid and list. |
| Grid actions and metadata are incomplete | Tiles omit visible source, last-read time, pin state and action menu; favorite is only screen-reader text. Grid Continue does not handle middle click. | Provide a compact action menu, consistent modifier/middle-click behavior, visible favorite and readable source/progress. |
| Library accessibility semantics are incomplete | Rows use `role=option` with interactive descendants, no focusable row or listbox focus owner, and no active-descendant connection. j/k changes component state, not accessible focus. | Use semantic rows with separate detail/Continue buttons, or implement a complete composite-widget focus model. Test screen-reader announcements. |
| Long menus can leave the viewport | `.menu` has no maximum height or vertical scrolling. Position clamping cannot make a menu taller than the viewport fit. | Bound height to the viewport and allow scrolling; test a multi-source item at a short window height. |
| Narrow layout handles only part of the interface | The 300px breakpoint mainly hides the brand/source and changes list Continue to an icon. Detail controls, source rows, queue actions and long menus have no equivalent adaptations. | Verify 280/320/380/480px widths with long titles, specials and multiple sources. Collapse secondary actions deliberately. |
| Loading/error states are unfinished | `HomeView` returns nothing until the library loads. Its error output can surface raw error messages and has no Retry. | Use a quiet loading state, precise error text, Retry and a route to local diagnostics. |

### Proposed visual direction

See [the interactive light/dark prototype](ui-direction.html). It is a separate design artifact with clearly labeled fictional data, local placeholder artwork, and no network or persistence. DOM checks exercised search, favorite filtering and destination feedback; it has not been visually validated in a live browser.

The reference suggests **cobalt ink and halftone printing**:

- Saturated cobalt around `#2421DB`, warm paper `#F8F7F1`, dark ink `#191B30`; night surfaces around `#181925`, with a lighter blue accent for text.
- A small cobalt masthead with a low-contrast stippled print motif, kept away from functional text. The actual library should keep original cover colors.
- One prominent Continue destination with chapter and incomplete progress. Suppress duplication when the same series is already the current-page item.
- Compact 2:3 covers, crisp typography, 1px separators, small rectangular update badges, and 5–8px corners. No remote font or asset requirements.
- Secondary reading actions live in a consistent menu. Status/rating/editing move below the primary Continue/progress group in detail view.
- A detail page organized as reading action → position → metadata → chapters/sources → notes/history, with short readable labels.
- Match light, dark, empty, loading, error, selected and keyboard-focus states in the same design system.

The aesthetic can be implemented in the existing React/CSS stack. Introducing a component framework would add migration work without addressing the audit findings.

## Recommended implementation order

1. **Protect data and privacy:** A1–A5 and A7, export filtering, failure reporting. Add the reproduced cases to normal regression coverage as each fix lands.
2. **Fix source and tracking lifecycle:** A6, pending-observation retry, restored-page tracking, cover failure/retry state, serialized update checks. Validate worker termination and actual chapter navigation.
3. **Ship the visual refresh with interaction fixes:** shared colors/type/spacing, primary Continue hierarchy, detail hierarchy, modal focus, grid selection/actions, menu sizing and narrow layout. Verify real cached covers and all major states in both themes.
4. **Close fallback and verification gaps:** manual add/reassociation, representative live-site snapshots, import/export UI tests, 1,000-item browser performance checks and screen-reader testing.

Success should be measured by the original acceptance flow: automatically discover a series and local cover, open 31, finish it, make 32 current, restart, and Continue to 32. Extend that flow with corrected metadata, failed writes, an unavailable source and an offline library. The UI refresh is complete only when those behaviors remain dependable.
